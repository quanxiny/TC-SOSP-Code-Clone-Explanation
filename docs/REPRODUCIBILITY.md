# Reproducibility guide

## Environment and upstream detector

Run `bash tools/bootstrap_upstream.sh`, then create the reference Python 3.8,
CUDA 11.1, PyTorch 1.8, PyG 2.0.1, and JDK 8 environment through the patched
detector's `scripts/setup_environment.sh`. The patched detector supplies the
batched graph encoder and corrected data loader used by all explainers.

## Data

Natural-pair C9 reads the fragment-disjoint GCJ validation split from the
pinned detector checkout. The C8 and C10 transformation bundles are included
under `external_data/explanation_truth/`, including source variants, normalized
graphs, node mappings, known irrelevant nodes, pair manifests, and hashes.
These sets are derived from validation data only.

## Checkpoint dependencies

The GCJ checkpoint and CodeNet checkpoint hashes are recorded in the root
README and every run summary. C10 and C15 expect the CodeNet checkpoint
generated by the separately released continual-learning repository. This is a
model dependency only; no continual-learning implementation is included here.

## Run order

Use C1 as the primary method configuration. C2--C7 and C11--C13 inherit it for
budget, predictor, semantic-control, attention-control, and objective studies.
C9 adds strong natural-pair baselines. C16--C18 complete the stochastic
explainer seeds. C8/C10 use transformation truth, and C15 uses negative-pair
truth.

Every run is launched with:

```bash
"$PYTHON" research_cli.py --config CONFIG.json --device cuda:0
```

Output directories refuse incompatible resume configurations by hash. Test
data must remain sealed; all method development and comparisons use validation
data or validation-derived transformations.

## Verification

```bash
bash tools/verify_release.sh --full
```

This verifies configuration inheritance, artifact hashes, absence of private
review files, and the graph-pair explanation test suite.
